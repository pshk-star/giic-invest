## 2. Qué métricas se muestran realmente

Se muestran **solo cuando existe dato fiable**, cada una con etiquetas de **período · fuente · moneda ·
calidad**:

| Bloque | Métricas |
|---|---|
| Resultados | Ingresos (anual) + crecimiento interanual, Margen operativo, Margen neto, Utilidad neta (anual) |
| Por acción | EPS anual, EPS TTM (diluido, split-safe) |
| Flujos | OCF (anual), CAPEX (anual), FCF (anual), FCF (TTM) |
| Balance | Caja, Deuda neta |
| Retornos/múltiplos | ROE, P/E (sobre EPS **anual**, etiquetado explícitamente), FCF yield (con P/FCF derivado) |
| Histórico (gráficos) | Ingresos; Márgenes neto/operativo; Free Cash Flow; Caja vs Deuda neta — últimos ~6 ejercicios de `companyfacts` EDGAR |

**Distinción de períodos y fuentes (requisito central):**
- Cada KPI lleva badge de período: `Anual` / `TTM` / `Trim` / `YTD` / `Balance` / `Período ?`.
- Badge de fuente: **EDGAR** (verde, ancla oficial) o **EODHD** (ámbar, interino).
- Badge de calidad cuando no es `verificado`: `parcial`, `desactualizado`, `inconsistente`.
- Badge `valoración` solo si el período/definición es apto — y el panel aclara que **apto ≠ verificado**.
- Moneda **nativa** siempre (USD / EUR / TWD), sin forzar USD ni mezclar divisas.
- La cabecera separa "último ejercicio EDGAR" de "interino EODHD al" (dos fechas distintas).

## 3. Qué métricas siguen sin datos (y por qué, sin estimarlas)

- **ROIC** → "no disp." No se calcula de forma fiable con datos oficiales gratuitos; no se inventa.
- **EV/EBITDA y EBITDA** → nota explícita "no disponibles de forma confiable…; no se estiman".
- **P/E forward** → requiere consenso de analistas (no gratuito); se omite.
- **EPS / P/E en algunos internacionales** (p. ej. RACE) → EDGAR no expone EPS por ADR comparable;
  se deja en "—" en lugar de fabricarlo.
- **Margen operativo, FCF, caja, deuda neta en bancos** (p. ej. JPM) → conceptos no aplicables o no
  comparables para una entidad financiera; se muestran "—" y los gráficos de FCF/caja indican
  "Sin serie suficiente" en vez de forzar una línea.
- **Cualquier campo EODHD interino que no sea apto** (trimestre individual, YTD, EPS EODHD) →
  se muestra su recencia pero **nunca** se marca `valoración`.

## 6. Limitaciones relevantes para Fair Value (fase siguiente)

1. **Sin múltiplos de empresa completa fiables:** EV/EBITDA, EBITDA y P/E forward no están
   disponibles con datos gratuitos. Un Fair Value por múltiplos EV/EBITDA requerirá otra fuente o
   deberá limitarse a P/E (anual) y FCF yield.
2. **ROIC ausente:** no hay ROIC persistido; un modelo de calidad/retorno tendrá que derivarlo con
   cuidado (NOPAT y capital invertido no están resueltos hoy) o declararlo faltante.
3. **Interinos no aptos:** OCF/FCF interinos (YTD en ASML, trimestrales en TSM) y EPS de EODHD **no**
   deben alimentar un Fair Value directo; solo los campos `valuation_eligible=true`
   (anual / TTM / balance no ambiguo) son utilizables.
4. **Bancos y aseguradoras:** FCF, deuda neta y EV no aplican; el Fair Value de financieras necesitará
   un método propio (p. ej. P/TBV o ROE-vs-coste de capital), no el genérico de FCF.
5. **Cuarentena = dato ausente, no corregido:** los campos en cuarentena (JPM `revenue_annual`,
   RACE `ocf_annual`) no deben usarse como entrada; el Fair Value debe tratarlos como faltantes.
6. **Internacionales sin ancla SEC:** cuando una empresa sea `source_kind=eodhd_primary`, el Fair
   Value debe reflejar la menor confianza de la fuente (hoy ninguna de las 6 validadas lo es, pero el
   camino on-demand puede producirlas).

Con esto, la base para **Fair Value V1** es: usar únicamente campos anuales/TTM/balance aptos,
en moneda nativa, con P/E (anual) y FCF yield como múltiplos primarios, y tratar cuarentena e
interinos no aptos como datos ausentes.
